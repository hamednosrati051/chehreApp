# بک‌اند اپ جدید (فقط تصویر) — نسخه‌ی اول

سرویس جدا از نورا. هیچ ایمپورتی از کد نورا ندارد، هیچ جدولی از دیتابیس
نورا را نمی‌خواند و هیچ مقداری از `.env` نورا را استفاده نمی‌کند.
بخش صدا پارک شده و در این نسخه هیچ UI یا route صدایی ندارد.

## اصول جداسازی (قانون حامد)

- دیتابیس جدا: `new_app` (فایل `../db/schema.sql`) — فقط جدول‌های `app_*`.
- مدل‌های تصویر و صدا: فقط در بخش «مدل‌ها»ی زیرشاخه‌ی ادمین خود اپ
  تعریف می‌شوند؛ ردیف‌های نورا نه استفاده می‌شوند نه دست می‌خورند.
- پیامک OTP: با سرویس ملی‌پیامک فرستاده می‌شود، ولی مشخصات
  (نام کاربری، رمز، body/template) از env/تنظیمات خود اپ می‌آید —
  چیزی از تنظیمات نورا کپی نشده.
- گالری: کاملاً جداست. تایید در ادمین خود اپ انجام می‌شود و عکس
  تاییدشده فقط داخل خود اپ منتشر می‌شود؛ هیچ کپی‌ای در گالری نورا
  نوشته نمی‌شود و هیچ تماسی با دیتابیس نورا وجود ندارد.
- خرید بازار: با SKUها و کلید RSA خود اپ (از پنل بازار خود اپ)،
  نه کلید نورا.

## ساختار

```
backend/
  run.py            # اجرا روی پورت 5001 (با نورا تداخل ندارد)
  app/
    __init__.py     # Flask factory
    config.py       # فقط env خود اپ
    extensions.py   # db
    models.py       # مدل‌های SQLAlchemy مطابق db/schema.sql
    routes.py       # auth / worlds / singers / generations / coins / gallery
    worker.py       # Celery: صف تولید عکس و صدا
    services/
      coins.py      # موجودی، دفتر سکه، شارژ موقع تحویل
      sms.py        # ارسال OTP (MeliPayamak با config خود اپ)
      image.py      # ویرایش/تولید تصویر OpenAI-compatible (مثل Sunburst)
      voice.py      # اینترفیس تبدیل صدا — پیاده‌سازی بعد از انتخاب route
```

## راه‌اندازی (فقط env خود اپ)

| متغیر | توضیح |
|---|---|
| `APP_SECRET_KEY` | کلید امضای JWT (حتماً در محیط واقعی ست شود) |
| `APP_DATABASE_URL` | آدرس دیتابیس جدای اپ، مثل `mysql+pymysql://user:pass@127.0.0.1:3306/new_app` |
| `APP_CELERY_BROKER_URL` / `APP_CELERY_RESULT_BACKEND` | Redis صف (پیش‌فرض دیتابیس 1 ردیس لوکال) |
| `APP_SMS_API_URL`, `APP_SMS_USERNAME`, `APP_SMS_PASSWORD`, `APP_SMS_SENDER`, `APP_SMS_BODY_ID` | مشخصات پیامک خود اپ |
| `APP_BAZAAR_RSA_PUBLIC_KEY` | کلید RSA عمومی خود اپ از پنل بازار خود اپ (تا ست نشده، تایید خرید fail می‌شود و سکه‌ای شارژ نمی‌شود) |
| `APP_ADMIN_TOKEN` | توکن ادمین خود اپ، هدر `X-Admin-Token` (تا ست نشده، همه‌ی ‎/admin بسته‌اند) |

## Seed (مدل تصویر خود اپ)

```bash
cd backend && APP_DATABASE_URL=... python seed.py
```

ردیف مدل `gpt-image-2.5-sunburst` (AvalAI، کیفیت medium) را در
`app_models` خود اپ می‌سازد + تنظیم `image_coin_price=5` + پک تست
تحویل («تست»، ۵ سکه، ۱٬۰۰۰ تومان، `bazaar_sku=test_pack`). کلید
AvalAI در seed نیست؛ از فرم مدل ادمین خود اپ وارد می‌شود
(`PATCH /api/v1/admin/models/<id>`).

## تست پرداخت (پک «تست» — فقط بازار، نه زیبال)

درگاه پرداخت اپ فقط بازار است (Bazaar IAB)؛ هیچ مسیر زیبالی در
بک‌اند یا اپ نیست. روند تست پک «تست»:

1. در پنل بازار خود اپ یک محصول consumable با SKU یکسان با پک بساز
   (اگر SKU واقعی با `test_pack` فرق دارد، همان مقدار را در ادمین
   خود اپ روی پک «تست» هم بگذار)؛ قیمت پنل باید با `price_toman`
   پک یکی باشد — تومان × ۱۰ = ریال (برای پک تست: ۱٬۰۰۰ تومان =
   ۱۰٬۰۰۰ ریال).
2. در اپ، از پروفایل پک «تست» را بخر (خرید از سرویس بازار).
3. اپ `purchase_data` + امضا را به `POST /coins/purchases/verify`
   می‌فرستد؛ سرور امضای RSA (کلید پنل خود اپ) را چک می‌کند،
   `pack.coins` را شارژ می‌کند و خرید را `consumed` می‌کند.
4. موجودی سکه باید ۵ تا بالا رفته باشد؛ خرید همان پک باید بلافاصله
   دوباره ممکن باشد (consumable) و خرید تکراری همان توکن هرگز دوبار
   شارژ نمی‌شود (idempotency با `purchase_token`).
5. اگر خرید ناتمام ماند (وریفای شد ولی consume نشد یا برعکس)، با
   بازشدن دوباره‌ی اپ یا دکمه‌ی «بازیابی خریدهای ناتمام» در پروفایل
   بازیابی می‌شود.

## حالت تست (پیش از انتشار — سکه‌ی تستی بدون پرداخت)

برای وریفای چرخه‌ی کامل سکه ← تولید ← گالری قبل از انتشار بازار،
بدون نیاز به خرید واقعی:

```bash
curl -X POST /api/v1/admin/test/grant-coins \
  -H "X-Admin-Token: <توکن ادمین خود اپ>" \
  -d '{"user_id": <id کاربر>, "coins": 25}'
```

- فقط با توکن ادمین کار می‌کند؛ کاربر عادی نمی‌تواند به خودش سکه
  بدهد. سقف هر شارژ ۱٬۰۰۰ سکه است.
- در دفتر سکه با `reason=test` و `ref_type=test_grant` ثبت می‌شود،
  پس با خریدهای واقعی (بازار) قاطی نمی‌شود.
- با `APP_TEST_GRANTS_ENABLED=false` بسته می‌شود (مثلاً بعد از
  انتشار). پرداخت واقعی در هر حالت فقط بازار است.

## گام‌های پنل بازارِ حامد (پیش از انتشار)

1. اپ را در پنل بازار خود اپ ثبت کن (نام/پکیج نهایی، همان پکیجی که
   موقع انتشار استفاده می‌شود).
2. کلید RSA عمومی پنل را بگیر و در env خود اپ بگذار
   (`APP_BAZAAR_RSA_PUBLIC_KEY`)؛ کلید هرگز در کد نمی‌آید. تا وقتی
   ست نشده، تایید خرید fail می‌شود و سکه‌ای شارژ نمی‌شود.
3. SKU پک تست را در پنل بساز (consumable؛ برای پک «تست»: ۱۰٬۰۰۰
   ریال) و همان SKU را در ادمین خود اپ روی پک «تست» بگذار.
4. APK امضاشده (با همان کلیدی که موقع انتشار استفاده می‌شود) را
   در پنل آپلود کن.
5. خرید تستی را در اپ انجام بده و چک کن: سکه شارژ شد، خرید consume
   شد، خرید مجدد همان پک بلافاصله ممکن است.

## API (پیش‌فرض `/api/v1`)

- `POST /auth/otp/request` — ارسال کد ورود (موبایل)
- `POST /auth/otp/verify` — تایید کد و صدور توکن (۳۰ روزه)
- `GET /worlds`, `GET /worlds/<id>`, `GET /categories`
- `POST /generations` — ثبت job (بدون کسر سکه؛ تعرفه ۵ سکه، دنیا اگر قیمت دیگری داشته باشد همان)؛ `GET /generations/<id>`، `GET /generations/mine`
- `GET /coins/balance`, `GET /coins/ledger`, `GET /coins/packs`
- `POST /coins/purchases/verify` — وریفای RSA + شارژ سکه (idempotent) + مصرف؛ `GET /coins/purchases/pending`
- `POST /gallery/submit` — ارسال تصویر به صف تایید؛ `GET /gallery/mine`, `GET /gallery/public`
- ادمین (هدر `X-Admin-Token`): `GET/PATCH /admin/models`، CRUD
  `/admin/worlds`، CRUD `/admin/packs`، `GET /admin/gallery/pending`،
  `POST /admin/gallery/<id>/approve|reject` (تایید = انتشار فقط داخل خود اپ)

## وضعیت نسخه‌ی اول

- آماده: مدل‌ها، OTP، سکه (هدیه‌ی ۱ عکس اول، بعد سکه؛ کسر فقط موقع
  تحویل موفق)، دنیاها + ادمین دنیاها، ثبت job، ویرایش تصویر AvalAI
  با Sunburst و کیفیت medium، صف Celery، آپلود فایل (S3 با باکت خود
  اپ — موقع استقرار به env های S3 نیاز دارد)، پک‌ها + ادمین پک‌ها،
  وریفای خرید بازار با RSA + idempotency + مصرف، بازیابی خریدهای
  ناتمام، گالری کاملاً جدا با تایید ادمین خود اپ، لاگ هزینه‌ی واقعی
  AvalAI هر تولید (با usage گزارش‌شده).
- پارک‌شده (عمداً، نه در این نسخه):
  - `services/voice.py`: تبدیل صدا — route هنوز انتخاب نشده.
  - گالری نورا: هیچ کپی‌ای نوشته نمی‌شود؛ گالری اپ کاملاً جداست.
